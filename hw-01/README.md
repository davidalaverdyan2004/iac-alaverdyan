# Стенд для показов продукта (ДЗ 1, вариант 04)

Стенд поднимается перед показом одной командой и сносится после него, чтобы между
показами не платить за облако. Он переживает отказ одной машины: запросы принимает
балансировщик и раздаёт их между несколькими веб-серверами в двух зонах доступности.

## Из чего состоит

| Ресурс | Имя | Где |
|---|---|---|
| Сеть | `alaverdyan-04-net` | регион ru-central1 |
| Подсети | `alaverdyan-04-subnet-a`, `alaverdyan-04-subnet-b` | 10.14.1.0/24 в ru-central1-a, 10.14.2.0/24 в ru-central1-b |
| Веб-серверы | `alaverdyan-04-web-1` … `web-N` | зоны a и b по очереди, с публичным адресом |
| Сервер приложения | `alaverdyan-04-app` | ru-central1-a, **без публичного адреса** |
| NAT-шлюз и таблица маршрутизации | `alaverdyan-04-nat`, `alaverdyan-04-rt` | выход в интернет для подсети a |
| Целевая группа и балансировщик | `alaverdyan-04-tg`, `alaverdyan-04-lb` | принимает на 80, раздаёт на 8012 |

Все машины настраиваются при первой загрузке через `cloud-init.tpl.yaml`: nginx на порту
8012 отдаёт строку `devlab on <имя машины>`.

## Что нужно заранее

- bash (Linux, macOS или WSL), `yc` с настроенным профилем (`yc init`), `jq`, `curl`,
  `envsubst` (пакет `gettext-base`);
- ключ SSH в `~/.ssh/id_ed25519.pub`: он попадает на машины через cloud-init.

## Как пользоваться

Команды выполняются из корня репозитория.

```bash
./hw-01/create.sh      # поднять стенд (5–8 минут, ждёт готовности веб-серверов)
./hw-01/check.sh       # проверить; код возврата 0 — всё в порядке
./hw-01/destroy.sh     # снести всё, что начинается с префикса
```

`create.sh` можно запускать повторно: существующие ресурсы пропускаются, дубликаты не
создаются. Последняя строка вывода — адрес балансировщика.

## Параметры

Приоритет: аргумент командной строки > переменная окружения > умолчание варианта.

| Аргумент | Переменная | По умолчанию |
|---|---|---|
| `--web-count N` | `WEB_COUNT` | 3 |
| `--port N` | `APP_PORT` | 8012 |
| `--greeting WORD` | `GREETING` | devlab |
| `--prefix NAME` | `PREFIX` | alaverdyan-04 |

```bash
./hw-01/create.sh --web-count 2
WEB_COUNT=4 ./hw-01/create.sh
./hw-01/create.sh --print-params     # показать итоговые значения, ничего не создавая
```

Одинаковые параметры передавайте всем трём скриптам: `check.sh` и `destroy.sh` ищут
ресурсы по тому же префиксу.

## Если check.sh вернул ошибку

`check.sh` печатает по строке на проверку и завершается с кодом 1, если хоть одна не прошла.

| Строка с ✗ | Что проверить |
|---|---|
| балансировщик не найден | стенд не поднят или снесён: `./hw-01/create.sh` |
| балансировщик отвечает не 200 | состояние машин: `yc load-balancer network-load-balancer target-states --name alaverdyan-04-lb --target-group-id <id>` |
| ответили не все веб-серверы | одна из машин UNHEALTHY: nginx остановлен или машина прервана облаком (`yc compute instance list`, статус STOPPED → `yc compute instance start <имя>`) |
| сервер приложения недоступен | на нём не завершился cloud-init: машина без публичного адреса ставит nginx через NAT-шлюз; проверьте привязку таблицы маршрутизации к подсети a и пересоздайте машину |
| не удалось подключиться ни к одному веб-серверу | SSH до облака недоступен из вашей сети: повторите проверку позже или из другой сети |

Машины прерываемые: облако может остановить любую из них. Это не поломка, а плата за
дешёвый стенд; повторный `./hw-01/create.sh` дорастит недостающее, а остановленную машину
запускает `yc compute instance start`.

## Стоимость

Стенд оплачивается только пока поднят. Расчёт по калькулятору Яндекс Облака — в отчёте.
После показа всегда запускайте `./hw-01/destroy.sh` и проверяйте, что списки пусты.
